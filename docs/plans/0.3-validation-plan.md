# 0.3.0 Validation & Release Plan

Single source of truth for what 0.3.0 needs before tagging. Combines:
- The audit deficiencies (`docs/plans/audit-findings.md` — this conversation's audit)
- The hermes team's validation plan (`cells/hermes/VALIDATION.md`)
- The brig-side support work the hermes team's `HERMES-MODIFICATIONS.md`
  implies brig must already do correctly.

Every item has a **Proof** field. An item is done when its proof passes
under CI **or** under `make smoke`-style local run (where noted).

Phases are ordered by release-blocking weight. A release-blocking item
cannot be deferred without explicit decision.

---

## Phase A — Release blockers (must complete to tag v0.3.0)

### A1. Cross the validation gate (hermes end-to-end)
Source: VALIDATION.md, audit deficiency #1.

Run `cells/hermes/VALIDATION.md` phases 0–4 against a brig built from
the current branch, on a freshly-up'd VM. Capture pass/fail per phase.

| Sub | What |
|---|---|
| A1.1 | Phase 0 preconditions: `brig --version`, `brig health`, `brig profiles`, host aitelier reachable |
| A1.2 | Phase 1: image builds, plugin loads (`get_provider_profile('aitelier')` returns class) |
| A1.3 | Phase 2: secrets added, cell stays running |
| A1.4 | Phase 3.1–3.5: aitelier backend works (LLM route, agent route, multi-turn+cancel, keepalive, persistent state) |
| A1.5 | Phase 4.1–4.4: OpenRouter backend works, egress filtering provable, switching back to aitelier requires no rebuild |
| A1.6 | (Optional, defer if not wired) Phase 5: Telegram gateway lights up |

**Proof:** every phase's `Pass:` criterion observed. Record actual
`brig logs`, `brig network`, and exit-code output for each phase in
`cells/hermes/VALIDATION-RUN-<date>.md`. Triage findings filed back
into this plan as new sub-items.

**Effort:** L (multi-hour wall time, mostly waiting on cell runs).

**Dependency:** Hermes side has the aitelier provider plugin merged or
present in `cells/hermes/hermes-src/` (local mode). If plugin missing,
A1.4 + A1.5 collapse to "image+egress works" only.

### A2. Pin gVisor — close task #44
Source: audit deficiency #2.

`src/brig/vm/lima.yaml.template` currently fetches
`storage.googleapis.com/gvisor/releases/release/latest/runsc` and its
sha512 from the same origin. Replace with version-pinned URLs + literal
sha512 (one per arch).

**Proof:**
1. `grep "release/latest" src/brig/vm/lima.yaml.template` returns nothing.
2. `scripts/pin-gvisor.sh` is idempotent — running it twice produces
   no diff.
3. New CI job re-fetches the pinned URL, computes sha512, asserts equal
   to the literal in the template. Drift fails CI.
4. `make reset && make setup` succeeds, `limactl shell brig -- runsc --version`
   prints the expected version.

**Effort:** S (1–2 hours including the CI guard).

---

### A3. `brig up` lies when warden isn't really running
Source: audit deficiency #10.

In this session we saw `brig up` print "Proxy is already running" while
the container did not exist. Likely `_can_start` short-circuits on a
cached or stale check.

**Proof:**
1. New test `tests/test_brig_up_state_check.py`: `proxy_running()` returns
   False, `brig up` invokes the start path, container is created.
2. New test: `proxy_running()` returns True, container actually exists →
   "already running" is correct.
3. New test: `proxy_running()` returns True but inspect says exited →
   `brig up` recovers by restarting (or fails closed with a clear error,
   choose one).

**Effort:** S.

---

### A4. First-run integration test
Source: audit deficiency #4. **Defends A1 from regression.**

A scripted "fresh-machine" test that captures the first-run failure modes
we just hit (missing addons, missing dirs, sudo lag, wrong field name,
etc.). Run on each PR.

**Proof:** new `scripts/fresh-install-test.sh` does:
1. `make reset` (or simulate by `rm -rf ~/.brig` + `limactl delete brig -f`).
2. `make setup`.
3. `brig health` — expect both checks `[OK]` and total wall time < 5 s.
4. `brig run --name fresh-test alpine echo hello` — expect cell exits 0
   and output is captured.
5. `brig rm -f fresh-test` — exits 0.

Wired into `.github/workflows/e2e.yml` on `macos-15` runner; cron-weekly
+ on every PR that touches `src/brig/vm/**` or `Makefile`.

**Effort:** M. CI wall time per run ~10 minutes.

## Phase B — Test suite reaches the boundary

These close the structural gap the audit identified: tests mock the very
seam that actually fails in production.

### B1. Schema-pin podman output
Source: audit testing finding §3.

Snapshot real `podman inspect` and `podman ps -a --format json` from a
known podman version into `tests/fixtures/podman/<version>/*.json`.
Refactor `verify.py` tests to load from fixtures instead of hand-crafted
JSON.

**Proof:**
1. `tests/fixtures/podman/5.0/inspect_warden.json` etc. exist.
2. `tests/test_security_verify.py` uses them.
3. New CI matrix job: install podman from a known version, regenerate
   fixtures, assert byte-equal (fails on drift).

**Effort:** M.

---

### B2. Rollback-of-rollback test
Source: audit testing finding §1, deficiency #9 (related).

Reconciler's `_rollback` swallows exceptions per-action; no test asserts
the loop continues after a rollback throws. Inject a failure in one
rollback action, assert later rollbacks still execute.

**Proof:**
1. New `tests/test_reconciler_rollback_resilience.py`: monkey-patch
   `_execute_action` to raise on `REMOVE_NETWORK`; assert `FREE_SUBNET`
   still runs.
2. Assert the original failure's exception text is preserved in
   `result.actions_failed`.

**Effort:** S.

---

### B3. Real `PODMAN_RUN` rollback coverage
Source: audit deficiency #9.

Today `PODMAN_RUN` is last in the plan so rollback isn't exercised. Add
a test that constructs an action list ending in a synthetic post-RUN
action (or refactors so RUN can fail after partial execution), and
assert the container is `rm`'d.

**Proof:**
1. New test inserts a failing action after `PODMAN_RUN`.
2. Assert `podman rm <container>` appears in the mock's call history.

**Effort:** S.

---

### B4. WebSocket-through-warden test
Source: hermes `HERMES-MODIFICATIONS.md` §6, audit deficiency #3.

Gateway adapters (Telegram long-poll, Discord WSS, Slack Socket Mode)
must work through warden. Today untested. Build a fixture that opens a
`wss://` to a local mitmproxy-friendly test server (or to a small in-VM
echo) through warden and asserts bidirectional message flow.

**Proof:**
1. New `tests/e2e/test_websocket_through_warden.sh` (or pytest):
   - Stand up an in-VM `python -m websockets.serve` on
     `wsproxy-target.host.brig`.
   - Run a cell that opens a `wss://` to it through `http_proxy`.
   - Assert ping/pong succeeds.
2. Document any addon changes required (mitmproxy may need explicit
   websocket script enable).

**Effort:** M.

---

### B5. SSE / keepalive passthrough test
Source: hermes VALIDATION.md Phase 3.4, audit deficiency #3.

Aitelier emits `:keepalive` SSE comments every ~25 s during silent
phases. Mitmproxy can buffer responses; need to assert that doesn't
happen for `text/event-stream` Content-Type.

**Proof:**
1. New test: cell makes a request to a fixture endpoint that emits SSE
   `:keepalive` over 60 s; cell sees each comment within ≤ 2 s of
   emission.

**Effort:** S–M.

---

### B6. Coverage gate on the modules that matter
Source: audit testing finding §6.

Today: global 65 % floor. Replace with per-package gates:
- `src/brig/security/**` ≥ 90 %
- `src/addons/enforce.py` ≥ 90 %
- `src/brig/cell/reconciler.py` ≥ 85 %
- Everything else ≥ 60 %

**Proof:** `.coveragerc` (or `pyproject.toml`) declares per-package
thresholds. PRs that drop a security module below 90 % fail CI.

**Effort:** S.

---

### B7. Wire `test_overhead.outcome` into E2E check loop
Source: audit testing finding §6.

Benchmark regressions currently don't fail CI because the outcome isn't
in the aggregation step.

**Proof:** `.github/workflows/e2e.yml` "Check results" step includes
`test_overhead.outcome`. Introduce a deliberate 50 % perf regression in a
PR; CI fails.

**Effort:** S (trivial workflow edit + one verification PR).

## Phase C — UX gaps surfaced by audit + hermes

### C1. `brig build` — image build wrapper
Source: audit deficiency #5, VALIDATION.md Phase 1.

Hermes today uses `cd cells/hermes && podman build ...`. Brig should
wrap that so the user doesn't need to know it runs in the VM:

```
brig build cells/hermes               # equivalent to:
                                       #   limactl shell brig -- sudo podman build \
                                       #     -t localhost/hermes-agent:latest \
                                       #     -f cells/hermes/Containerfile cells/hermes
```

**Proof:**
1. New `brig build <dir>` subcommand. Auto-derives image tag from dir
   name if not specified; supports `--tag`, `--build-arg`.
2. `tests/test_image_cmd.py` exercises arg-handling.
3. VALIDATION.md Phase 1 rewritten to `brig build cells/hermes`.

**Effort:** M.

---

### C2. `brig policy test` actually simulates the request flow
Source: audit deficiency #7.

Today `--path` and `--method` flags are accepted but ignored (`policy_cmd.py:113`).
Wire them through the same `PolicyRule.matches_*` path warden uses.

**Proof:**
1. Remove the "Note: --path/--method ignored" comment.
2. `tests/test_policy_test.py`: assert that a policy with
   `{ "domain": "api.x", "methods": ["GET"] }` allows GET but blocks POST
   when `--method POST` is passed.
3. Optional: print the matching rule and its origin (global vs per-cell)
   so the user knows *why* it was allowed/denied.

**Effort:** S.

---

### C3. `brig watch <cell>` — unified observability stream
Source: audit deficiency #8.

Multiplex cell stdout + warden network log + lifecycle events into one
stream, color-coded by source, tailable, `--follow` by default.

**Proof:**
1. New `brig watch <cell>` subcommand.
2. `tests/test_watch_cmd.py` confirms it correctly reads from all three
   sources and interleaves by timestamp.
3. `docs/learning/host-an-agent.md` step 5 updated to use `brig watch`.

**Effort:** M.

### C4. `cells/hermes/` becomes the canonical worked example
Source: hermes plan, audit deficiency #4 mitigation.

Cross-link `docs/learning/host-an-agent.md` ↔ `cells/hermes/`. Make
`cells/hermes/hermes.yaml` self-contained enough to be the example any
agent-author starts from.

**Proof:**
1. `docs/learning/host-an-agent.md` links to `cells/hermes/` as
   "production-shaped reference cell".
2. `cells/hermes/hermes.yaml` runs from a clean clone after `brig
   secrets add openrouter-key` — no edits required.

**Effort:** S.

### C5. Trim the CLI: collapse `brig health` into `brig doctor`
Source: audit code-quality finding §6.

`brig health` and `brig doctor` overlap heavily. `brig events` and
`brig history` overlap heavily. Two dispatchers (`brig preflight`,
`warden preflight`) do the same thing.

Smaller scope for 0.3: deprecate `brig health` in favor of `brig doctor
--quick`. Print a deprecation note for one release; remove in 0.4.

**Proof:**
1. `brig health` prints "Deprecated; use `brig doctor --quick`" to stderr.
2. `brig doctor --quick` exists and matches old `health` output shape.
3. `tests/test_cmd_handlers.py` covers both.

**Effort:** S.

---

### C6. Atomic-write + domain-matching dedup
Source: audit code-quality finding §3.

- Replace the open-coded atomic writes in `src/brig/network/subnet.py`
  with calls to `brig.ops.atomic.atomic_write_json` (keep the addon
  copy — it can't import).
- Replace `_matches` in `warden/cli.py:101` and `policy_cmd.py:122`
  with `PolicyRule.matches_domain`.

**Proof:**
1. `grep "tempfile.mkstemp\|os.rename" src/brig/network/subnet.py`
   returns nothing.
2. `grep "_matches\b" src/brig/commands/policy_cmd.py src/warden/cli.py`
   returns nothing.
3. All existing tests still pass.

**Effort:** S.

## Phase A is the release gate

Tagging `v0.3.0` requires:
- A1 fully green (all phases pass; triage items closed)
- A2 fully done (gVisor pinned + CI guard)
- A3 fixed and tested
- A4 wired into CI

Phase B and Phase C ship in 0.3.1 / 0.3.2 unless their proof landed
before tag. Phase D is 0.4 design.

## Ownership / handoff

Each phase is a candidate PR. PRs should reference this doc and update
the relevant item's status inline (✅ / 🟡 / ❌) as they land. When all
of Phase A is ✅, cut 0.3.0.
